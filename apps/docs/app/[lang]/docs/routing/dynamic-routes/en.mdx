A static route is one window. A pattern stands for as many windows as URLs
visited — one per document, task or record — which means it cannot be rendered
from a list the way a static route can. There is a hook for that.

## Declaring a pattern

A segment written `:like-this` matches anything. Patterns go in the same
`routes` array as everything else:

```tsx title="app/shell.tsx"
const ROUTES = [
  "/",
  "/documents",
  "/documents/:file",
] as const;
```

<Callout>
  This is DayOS’s own syntax and has nothing to do with Next’s folder names. Next
  still wants `app/documents/[file]/page.tsx` on disk; the colon form is how the
  desktop is told that this route means many windows.
</Callout>

## Rendering one app per open window

`useDynamicWindows` returns the windows a pattern has open right now, with the
params each one resolved to:

```tsx title="app/shell.tsx"
import { useDynamicWindows, type RouteParams } from "@dayos/next";

function DocumentApps() {
  const windows = useDynamicWindows("/documents/:file");

  return windows.map(({ href, params }) => (
    <DesktopApp id={href} key={href}>
      <DocumentShell title={params.file} />
    </DesktopApp>
  ));
}
```

The list comes from the desktop’s open windows, not from state of your own. The
desktop already knows which documents are open, and a second copy of that would
be one more thing to keep in sync.

### Why params come along

The matching already worked out what `:file` stood for. Without handing it back,
every caller would take the href apart again to recover what the pattern had
just told it. They arrive decoded, the way a Next page’s params do, so a window
gets the name of the thing rather than its URL spelling.

```tsx
function DocumentApps() {
  const windows = useDynamicWindows("/documents/:file");

  return windows.map(({ href, params }) => (
    <DesktopApp id={href} key={href}>
      <DocumentShell title={findDocument(params.file)?.name ?? params.file} />
    </DesktopApp>
  ));
}
```

## Windows with no icon

A document or a task has no standing place on the desktop: it is opened from the
list above it, and closing its window is the end of it. So the app for a pattern
instance usually renders a window and nothing else.

```tsx
function DocumentShell({ title }: { title: string }) {
  const content = useWindowRoute();

  return (
    <Window
      className="window"
      defaultPosition={{ x: 220, y: 140 }}
      defaultSize={{ width: 520, height: 460 }}
      keepMounted
    >
      <WindowHeader className="window-header">
        <WindowName className="window-title">{title}</WindowName>
        <WindowActions className="window-actions">
          <WindowExpand className="window-button">▢</WindowExpand>
          <WindowClose className="window-button">✕</WindowClose>
        </WindowActions>
      </WindowHeader>
      <WindowContent className="window-content">{content}</WindowContent>
    </Window>
  );
}
```

## Opening one

Nothing special. The window’s href is the URL, so a `Link` opens it, and nothing
in your code keeps a list of which documents have been visited:

```tsx title="app/documents/page.tsx"
export default function DocumentsPage() {
  return (
    <ul>
      {DOCUMENTS.map(({ file, name }) => (
        <li key={file}>
          <Link href={`/documents/${file}`}>{name}</Link>
        </li>
      ))}
    </ul>
  );
}
```

Opening a document leaves the list window alone. The list stays on its own page
while the document gets a window of its own beside it — which is the behavior
you would have to build by hand in a tabbed interface.

## Nesting

Patterns nest as deep as you like, and each level is a separate declaration:

```tsx
const ROUTES = [
  "/projects",
  "/projects/archive",
  "/projects/:project",
  "/projects/:project/new",
  "/projects/:project/:task",
] as const;
```

Stagger the geometry so opening one after another leaves all of them visible at
once:

```tsx
<PatternApps
  defaultPosition={{ x: 180, y: 120 }}
  pattern="/projects/:project"
/>
<PatternApps
  defaultPosition={{ x: 300, y: 240 }}
  pattern="/projects/:project/:task"
/>
```

<Callout
  type="warning"
  title="A pattern with a literal last segment is still a pattern"
>
  `/projects/:project/new` ends in a literal, but it still has a param — so it is
  one window per project rather than one window, and it belongs with the patterns
  rather than in the list of static routes.
</Callout>

## Splitting the list

Static routes are rendered one by one; patterns are rendered per instance.
Deriving the first list from the second keeps them from drifting:

```tsx title="app/shell.tsx"
const PATTERNS: readonly string[] = [
  "/documents/:file",
  "/projects/:project",
  "/projects/:project/new",
  "/projects/:project/:task",
];

const STATIC_ROUTES = ROUTES.filter((route) => !PATTERNS.includes(route));
```

## What a pattern does not claim

Only the windows the pattern itself owns come back from the hook. Declaring
`/documents/new` alongside `/documents/:file` keeps that one out of the list:
its window belongs to the specific route, not to the pattern. Which route wins
is [route matching](/docs/routing/matching).
